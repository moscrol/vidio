## 三、自查发现之二:你那条 PIT 风险,比缠论更广 —— 整个教学轨

你第 4 条说「部分缠论字段用完整历史重算时,会改变过去日期的结果」。我顺着查,**结论比这更严重**。

### 先排除一种可能:标注本身没偷看未来

`structure.py` 的事件记在 `b + k`(摆动低点 + k 的确认日),且有 `if b + k >= n: continue`。
一个记在第 i 天的事件,只用到 `close[..i]`。**标注是 PIT 干净的。**

### 真正的问题在重建怎么盖戳

```sql
-- scripts/teaching_framework.py:995
DELETE FROM history_teaching_labels WHERE entity_type = 'market'
-- 然后整批重插，computed_at = 本次构建时间
```

**每次重建都把所有历史行的 `computed_at` 刷成「今天」。**

而河的 PIT 闸是(`river.py:973-984`):

```python
kept = [o for o in result if o.recorded_at is not None and o.recorded_at[:10] <= cutoff]
# recorded_at 为 NULL 的一律滤掉：不可判等于不能证明当时已知，fail closed
```

教学对象的 `recorded_at` 取的就是 `computed_at`。

### 实测

```
当天教学对象: 7
   teaching_stage    trade_date=2026-01-12   recorded_at=2026-09-07T15:00:00
   teaching_capital  trade_date=2026-01-12   recorded_at=2026-09-07T15:00:00
   ...
按 knowledge_cutoff = 2026-01-12 过 PIT 闸之后：
   整条轨退化成 Gap → pit_filtered
```

**不是缠论独有,是全部教学标签;不是部分失真,是整条轨在任何历史日被完整滤掉。**

### 这意味着什么

- 我这两轮搬上判定路径的 **44 个教学标签**,在**任何 PIT 严格的历史切片上都看不见**。
  它们现在只在「今天」这种 cutoff ≥ 构建时间的切片里有效。
- 而你要的「**通过时间长河找规律,然后推未来**」—— 找规律**本质上就是历史回放**。
  在这个问题修掉之前,长河上的回测看不到任何教学标签。

### 这是闸错了还是数据错了

**闸是对的,别动它。**你确实无法证明 2026-01-12 那天就知道这条读数 ——
旁路库只记了「最后一次重算是什么时候」,没记「最早什么时候可知」。闸 fail closed 是正确反应。

要修的是旁路库:**`computed_at`(最后重算)之外,再记一个 `first_known_at`(最早可知日)**,
重建时对内容未变的行保留原值。河改读后者。

**这不是数据源问题 —— 同花顺补不了,换任何源都一样。** 而且换源意味着再来一次全量重算,
如果不先修戳记,**换源会把所有历史标签的 `computed_at` 再刷一遍**,问题只会更大。
