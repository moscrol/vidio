# 多维对照镜头(river-lens)—— 工具说明

**一句话:**它不换算法、不换距离、不换权重,只把被压扁的东西**摊开给 agent 看**。

交付在 `ALL-EIGHTEEN-merged.patch`(18 连,`148a09ec` 上 `git am` 干净)。
文件:`intelligence/services/river_lens.py` + `intelligence/tests/test_river_lens.py`。

---

## 它修的是什么

`market_regime_analogs.regime_block_for_llm` 递给 LLM 的是**成品答案**:

```
432 天 × 10 维
  → z 标准化 → 每窗每维 2 个数
  → 加权 L1（各维等权、_DELTA_WEIGHT=0.5 写死）
  ★ 塌成 1 个标量距离 ★
  → 排序取 top K
  → 每行只渲染 5 维的【窗口均值】，拼成一个字符串
```

于是 agent **看不到多维**(只看到 5 个均值)、**没法自己总结**(总结在它之前
用固定权重做完了)、**不能决定「类似」是什么意思**。

镜头把三样被压扁的东西摊开。

---

## 效果:同一份数据,两种读法

构造的局(`test_river_lens.py`):六个维度,其中三个 breadth 维共享同一条基序列
(历史相关 **1.00**),另三维互相独立。

### agent 现在收到的

```
| 历史相似窗口              | 距离 | 窗口内环境（均值）                              |
| 2024-04-08~2024-04-17 | 1.04 | 涨停3.0 · 连板3.0 · 新高3.0 · 资金0.3 · 舆论0.3 |
| 2024-07-15~2024-07-24 | 1.13 | 涨停0.0 · 连板0.0 · 新高0.0 · 资金3.0 · 舆论3.0 |
```

**→ 合理结论:窗口 A 距离更小,以它为对标。**

### 镜头给出的

```
### ① 维度结构：名义 6 维，实际 **4** 组
| 组 | 成员            | 组内最高 |r| |
| G0 | 涨停、连板、新高 | 1.00        |
| G1 | 资金            | —           |
| G2 | 舆论            | —           |
| G3 | 个股            | —           |

### ④ 候选窗口：像在哪、不像在哪
| 窗口   | 距离 | 对齐维            | **独立组数** | 分歧维（Δz 最大）                    |
| 窗口A | 1.04 | 涨停、连板、新高   | **1**       | 个股 Δ+2.1、舆论 Δ+2.1、资金 Δ+2.1 |
| 窗口B | 1.13 | 资金、舆论、个股   | **3**       | 涨停 Δ+2.3、新高 Δ+2.3、连板 Δ+2.3 |
```

**→ 两边都是「3 个维度吻合」,但 A 是一件事吻合、B 是三件独立的事吻合。
标量距离把这个区别抹掉了,而且抹掉之后排名是反的。**

## 摊开的三样东西

### ① 维度结构 —— 最重要的一样

按历史 `|r|` 把特征并组(平均连接层次聚类,距离 `1−|r|`,
与 `river_window.cluster_windows` 同款,合并顺序确定、可重算)。

回答:**「名义 N 维」里实际有几组。**

> 同组内的维一起吻合,**只算一件事吻合**。
> 不知道这件事,agent 必然高估「多个维度都吻合」的分量。

**对你的 10 维的预判(未实测):**`advancers` / `limit_up` / `max_boards` /
`new_high_count` / `double_red_theme_count` 都在量广度强度,**很可能塌成一组**。
真实数字要在你的库上跑才知道 —— 这正是这个工具第一件要回答的事。

**证据不足的处理:**共同观测少于 30 对时不判相关,单列 `undetermined`,距离按最远。
**宁可少并组** —— 错并会让 agent 低估吻合分量(误导),没并只是少给一条提示(不误导)。
读数里明写「**未并组 ≠ 已证明独立**」。

### ② 距离分解 —— 像在哪、不像在哪

逐维 `Δz`、对齐/分歧分类、每维对总距离的贡献,以及 **`aligned_groups`**:
对齐维落在几个**独立**组里。

**不建第二套距离** —— 有测试断言逐维贡献之和能还原成同一个 `signature_distance`。

### ③ 距离地形 —— 真的近,还是矮子里拔将军

`standout = (p5 − nearest) / (p50 − p5)`

| | 读数 |
|---|---|
| ≥ 1.0 | 真正突出的相似窗口 |
| 0.2–1.0 | 成立但不唯一,第 2–5 名几乎同样近 |
| < 0.2 | **全历史没有特别像的窗口** —— 更可能是「当前环境在历史上少见」,把 top-K 当对标会严重误导 |

> **这里有一个被测试抓出来的真 bug:**我最初用「最近者的百分位」判断突出与否。
> 但最近者按定义就是第 1 名,**那个数恒等于 0** —— 无论全历史真有一个极像的窗口,
> 还是两百个窗口一样不像。换成上面这个比值,分母是「近端→中位」的自然尺度,不随量纲变。

## 怎么用

```bash
python3 -m intelligence.services.river_lens \
    --knowledge-cutoff 2026-09-30 \
    --window 10 --step 5 --top 5
```

| 参数 | |
|---|---|
| `--knowledge-cutoff` | **必填**。站在哪天回看 |
| `--window` / `--step` | 窗口长度 / 候选铺设步长(交易日) |
| `--redundancy-r` | 并组阈值,默认 `0.7` |
| `--json` | 出结构化读数而不是文本块 |

---

## 纪律

| | |
|---|---|
| **只读** | 不建表、不写库、不联网 |
| **不建第二套距离** | 全部复用 `market_regime_analogs` 的三个函数。测试钉死分解能还原原距离 |
| **不自己连库** | `lens_from_db` **必须**走 `river_window.build_daily_vectors` —— 那里强制 `knowledge_cutoff`。另开取数路径就是另开一个漏 PIT 的口子。**有测试钉死** |
| **缺维不伪造** | 沿用上游:只在共有维上比、按覆盖率惩罚、缺的如实报 |
| **不重叠** | 与当前窗重叠的候选剔除 —— 自己跟自己像不是信息 |
| **特征集是参数** | 默认 `river_window.FEATURES`(六轨)。**教学标签接进来后,同一个工具直接量新维度,不用改代码** |

## 它**不**改善什么 —— 必须说清

1. **它不增加维度。**它只让你看清**现在有几维**。
   如果你的 10 维真塌成 3 组,这个工具会如实告诉你 —— 但**它不会帮你补上缺的维**。
   补维要靠接教学层、复活资金轨,那是另一件事。

2. **它不碰教学标签。**现在读的还是 `river_window` 的六轨。
   教学表 **0 行**,接进来也是空的。**特征集已经做成参数,放完水直接加,不用改代码。**

3. **它不判断好坏。**它说「A 像在一件事上、B 像在三件事上」,
   **不说哪个该信** —— 那是你的判断,不是算法的。

4. **它不解决「没有数据」。**资金轨 51 天且停用、舆论轨 2026-01 起、个股轨河上无主体 ——
   这些维在长区间上照样整维退出。镜头会**如实报出来**(`dropped_features`),
   但报出来不等于补上了。

5. **「10 维塌成几组」这个数我还没在你的库上跑过。**上面写的是预判,不是读数。
   这正是第一件该跑的事。
