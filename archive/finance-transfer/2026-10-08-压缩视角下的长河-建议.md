## 一、四层尺子,量你的系统

那段话给了四层:

> 定理是结果。证明是路径。理论是地图。**概念是坐标系。**

对照长河:

| 层 | 长河里是什么 | 现状 | 证据 |
|---|---|---|---|
| **定理 = 结果** | 每天每个实体的标签读数 | ✅ 有(51 个读数的目录) | 桥的 catalog |
| **证明 = 路径** | 这个读数从哪张表哪一列怎么算出来 | ✅ **有,而且做得好** | `river_window.FeatureSpec`:每维带 `source`(表.列)+ `rule`;`provenance` 链可拆到行 |
| **理论 = 地图** | 哪些区间彼此相似、分成几类 | ⚠️ **机器有,但地图没画出来** | `cluster_windows()` 能跑,但 `Cluster.to_dict()` 只输出 `size` / `labels` / `raw_means` —— **簇是一堆数字,没有名字** |
| **概念 = 坐标系** | 用哪组特征看世界 | ❌ **写死的** | `FEATURES` 是模块级 `tuple`。**只有一个坐标系,没有第二个可比,也没有「哪个更好」的度量** |

**卡在第四格。**而那段话说得很直白:最高级的创造恰恰在第四格 ——
**发明新坐标系,让一大片迷宫突然简单。**

### 还有一个断点,刚好在第三层和第四层之间

你的 BP 里有一个钦定词叫 **环境剧本**:

> 某类指数/流动性环境下,历史走过几次、共性、近期流动性出口、该环境下框架怎么读

**这就是「被命名的簇」—— 簇从数字变成概念的那一步。**

`[实测]` 全仓 `.py` 里 grep「环境剧本」→ **零命中**。
你自己的 BP v0.8 存档第 249 行写着:「**环境剧本对象与流动性出口待做**」。

所以链条是这样断的:

```
窗口 → 特征 → 距离 → 聚类 → 簇 ──╳── 命名 → 词表 → 下次直接用这个词读盘
                                  ↑
                          断在这里（环境剧本待做）
```

**簇不命名,就永远是第三层的数字,进不了第四层。**
下一次读盘还得从头算一遍距离,**没有任何东西被压缩下来、被复用。**

## 二'、核心发现:**agent 现在根本看不到多维** —— 降维在它之前就做完了

你说「让行情有多维度可以让 agent 去看到,让他有机会去总结」。
我去查了 **agent 实际收到什么**(`market_regime_analogs.regime_block_for_llm`,
这是递给 LLM 的那一块)。

### 管道是这样的

```
432 天 × 10 维 原始读数
   ↓ z 标准化
每窗口每维 2 个数（均值、首尾段变化）
   ↓ 加权 L1，权重写死（_DELTA_WEIGHT = 0.5，各维等权）
★★ 塌成 1 个标量距离 ★★
   ↓ 排序，取 top K
渲染成一张表：5 行
   ↓ 每行只显示 5 维（_DISPLAY_FEATURES）的【窗口均值】，拼成一个字符串
"成交额12345.6亿 · 涨停45家 · 最高连板6板 · 双红题材8个 · 偏离度1.2%"
```

### 所以 agent 拿到的是

| | |
|---|---|
| **算**的时候 | 10 维 |
| **给 agent 看**的时候 | **5 维,而且是窗口均值,拼成一个字符串** |
| 相似度 | **1 个标量** |
| 候选 | **top K 的成品名单** |

**agent 收到的是一个「已经做完的答案」,不是一个「可以在里面找的空间」。**

### 对照你的三个动词

| 你要的 | 现状 |
|---|---|
| **看到**多维度 | ❌ 它看到 5 个均值。10 维在它之前就塌成 1 个数了 |
| 有机会去**总结** | ❌ 总结已经做完了 —— 固定算法、固定权重。agent 只负责把结论念出来 |
| 去**寻找**类似的特征 | ❌ 它不能决定「类似」是什么意思。`_DELTA_WEIGHT=0.5`、各维等权,都是写死的 |

**这个架构把 LLM 当成渲染器,不是当成那个「去找」的人。**
按那段话的说法 —— **寻找表示这件事本身才是智能**,而这一步现在是硬编码的。

### 更底层的问题:名义六轨,实际只有一轨能进比较

`river_window.py` 自己的 docstring 写着(引 `scripts/river_pit_audit.py` 的读数):

| 轨 | 实际状态 |
|---|---|
| 盘面 | ✅ 有 |
| 题材 | ✅ 有 |
| **资金** | `fact_theme_flow_daily` **只有 51 天**,且因口径切换**整维停用** |
| **舆论** | **2026-01 才开始**,长区间上按覆盖率判为缺失、整维退出 |
| **个股** | 河上**无个股主体**(`resolve_entity` 只解析板块) |
| **判断** | `checkpoints.jsonl` 用户态文件,未提供路径时整维缺失 |

**所以「多维」目前基本是:盘面一条轨上的 10 个高度相关的数。**

而且那 10 个里 —— `advancers` / `limit_up` / `max_boards` / `new_high_count` /
`double_red_theme_count` —— **都在量同一件事(广度强度)**。
名义 10 维,**真正独立的维可能只有三四个**。

> **这才是 agent「总结不出东西」的真正原因:
> 不是它不会总结,是给它看的东西本来就没有多少维。**

## 二''、所以顺序是:先让维度存在,再让 agent 看见

两件事都要做,**但不能反**。给 agent 一个漂亮的多维视图,而底下只有三个独立维,
那是把空房间装修一遍。

### 第一步:让维度真的存在

按「增加真正的维度」排序,而不是按好做排序:

| 优先级 | 做什么 | 为什么是**新维度**而不是「加事实」 |
|---|---|---|
| **1** | **把教学层的组合接进特征空间** | 赚钱效应 / 指数阶段 / 板块角色是**同一批量价的另一种组合** —— 按那段话这是换表示。而且是唯一经过人验证的那套组合 |
| **2** | **资金轨复活** | 它是**真正不同的一轨**(谁在买),不是量价的再切片。但要先解决口径分组标准化(见 §七) |
| **3** | 舆论轨 | 真正不同的一轨,但历史只到 2026-01,长区间上注定缺失 |
| 4 | 个股轨 | 河上无主体,地基级工程 |

**注意第 1 条有个前提:要测它是否真的增加了独立维度。**
如果赚钱效应五定义和 `limit_up` 在历史上高度同步,
那接进去是「增加事实」,**不是**「换表示」—— 那就违背了你认可的那段话。

**这就是「综合起来」的诚实版本:综合 ≠ 堆叠,要测增量。**

### 第二步:把空间给 agent,而不是把排名给 agent

四处改动,都很便宜:

| 现在 | 改成 | 为什么 |
|---|---|---|
| 1 个标量距离 | **逐维距离向量** | 「在资金上像、在情绪上不像」—— 这是 agent 能总结的东西,标量不是 |
| top K 名单 | **加上距离分布** | 50 个窗口都在 1.2–1.4,和一个 0.3 其余 2.0,是完全不同的两件事。现在都看不见 |
| 5 维均值字符串 | **保留逐维 z 值**(当前窗 + 候选窗) | 均值把窗口内的演变也压没了 |
| 只报相似 | **同时报最大分歧维** | 防刻舟求剑(见 §七) |

**核心心法:把「为什么像」的分解交给 agent,别只给它「像不像」的结论。**

那段话说高手看见 A、B、C、D 是同一个问题 —— **前提是他能同时看见 A、B、C、D。**
现在 agent 看见的是别人替它排好的名次。

## 二、~~核心建议:给「深刻」一个读数~~ → 改为:**给「综合」一个验收标准**

> 初版这一节写的是「两个坐标系比武」,**已作废**(见顶部修正)。
> 但这个读数本身仍然要,**用途变了**:不是用来分胜负,是用来**验收「综合」有没有用**。

那段话里最可操作的一句:

> 真正好的压缩,必须同时做到:**压得足够短,又保留足够多的结构。**
> 压缩过度 = 欠拟合。压缩不足 = 过拟合。
> 真正的理解,是**用最少的假设,保留最大的解释力和预测力**。

**这句话是可以直接变成一个数的。**

### 怎么量

对一个坐标系 `S`(一组特征):

1. 取全部历史窗口,算**后续 20 日事实**的离散程度 `V_all`
   (`market_regime_analogs._forward_facts` 已经在算后续 5/10/20 日了)
2. 用 `S` 聚类,得到 K 个簇
3. 算**簇内**后续事实的离散程度,按簇大小加权 → `V_within`
4. **解释力 = 1 − V_within / V_all**

**必须留出法**:前 70% 历史上聚类定簇,**后 30% 从不参与**,只用来算解释力。
否则 K 调大就能把 `V_within` 压到 0 —— 那是过拟合,不是深刻。

### 这个数回答什么(**修正后的用途**)

**不是**「哪个坐标系赢」。是**增量验收**:

```
盘面 10 维                      → 解释力 a
+ 教学层组合（赚钱效应/阶段/角色）→ 解释力 b
+ 资金轨                        → 解释力 c
```

- `b > a` ⇒ 创始人的组合**确实换到了更好的表示** → 该接
- `b ≈ a` ⇒ 它和原始量价**量的是同一件事** → 接了是「增加事实」,不是「换表示」
- `c > b` ⇒ 资金轨是真的新维度 → 值得花力气复活

**每加一组维度就过一次这个闸。**这样「综合起来」才不会退化成「什么都往里塞」——
那恰恰是那段话反对的「增加描述世界所需要的独立事实数量」。

### 这不违反你的「不编概率」纪律

你的终局文档 §4 定了:**只报后续事实与复现次数,不编概率数字。**

要讲清楚区别:

| | |
|---|---|
| 禁止的 | 「当前环境下上涨概率 62%」—— 对**行情**编概率 |
| 这里要的 | 「这个坐标系把后续事实的不确定性降低了 31%」—— 对**坐标系**的度量 |

**一个是预测世界,一个是评价尺子。**后者是模型选择,不是预测,不触你的红线。
而且它恰好就是「复现次数」这个纪律的数学形式 —— 你那条纪律本来就是对的。

## 三、建议二:让坐标系变成一等公民

现在 `FEATURES` 是 `river_window.py` 里一个模块级 `tuple`。
**「换坐标系」= 改代码。**所以它实际上不可换,也不可比。

应该变成:**可命名、可版本化、可并排比较的对象**。

```
坐标系「量价十维」    → 解释力 0.xx（留出集）
坐标系「授课框架」    → 解释力 0.xx
坐标系「两者合并」    → 解释力 0.xx   ← 合并未必更好，这正是要测的
```

**为什么这件事比「再加几个特征」重要:**

那段话说,高手看到 A、B、C、D 是同一个问题。
**但系统得先能同时拿出两套看法,才谈得上比较哪套看得更远。**
现在它只有一套,而且那一套是量价。

### 你的授课框架不是「又 44 个特征」,是**唯一有外部验证的候选坐标系**

那段话说:

你的授课框架就是这个 —— 而且 **1000+ 学员用钱投过票**。
这是量价十维没有的东西(量价十维是工程师选的)。

**那就是你在指定坐标轴。**但 `[实测]` 相似性那三个模块里 grep `tf.` → **零命中**。
你指定的坐标轴,**对标引擎一个都看不见**。

## 四、建议三:先**测**冗余,不要先合并

那段话:

> 10,000 个事实变成了同一个结构的不同表现。

**减少独立事实数量 = 先知道哪些事实其实不独立。**

现成的靶子:**赚钱效应五个并列定义**
(`limit_top10` / `dual_red` / `rps5_top10` / `rank_mean_top10` / `kmeans_hot`)。

你说过五定义并列是**刻意**的 —— 我不动它。但应该能回答:

> 这五个定义在 432 个交易日里,**两两同时成立的比例是多少?**
> 有没有哪两个在历史上几乎从不分歧?

如果有两个一致率 98%,那它们**不是两个事实,是一个事实的两种说法**。
知道这件事**不等于**要合并它们 —— 决定权在你。
但现在的系统**连这个数都给不出来**,你就没法做这个决定。

同类可疑项:`regime` 的 `new_high_count` 和教学标签 `tf.new_high_1y_count` ——
看起来是同一个量被量了两遍,源头还不同。

### 把它变成项目的健康指标

我建议把汇报口径从

> ~~判定路径读数 4 → 27~~

换成

> **解释力 ÷ 独立事实数**

这个比值变大才是进步。**加特征会让分母变大,所以加特征不自动算进步。**
这条直接把我前几轮的优化方向给否了,但它是对的。

## 五、建议四:簇必须能被命名 —— 闭上压缩的环

那段话:

> 突然有一个数学家**创造了一个新概念**。在这个概念下面,
> 10,000 个事实变成了同一个结构的不同表现。

概念 = **被命名的压缩**。没有名字的簇不是概念,是中间结果。

你的词表里已经有这个词了(**环境剧本**),只是没实现。闭环应该是:

```
1. 窗口 → 聚类 → 簇
2. 簇通过解释力门槛（§2 的读数）→ 才有资格被命名
3. 命名 → 成为「环境剧本」对象 → 进词表
4. 下次读盘：先判「当前落在哪个环境剧本」，再在那个坐标系里读
5. 新数据进来 → 旧剧本的解释力下降 → 降级或重切
```

**第 2 步是关键,也是你和「随便聚个类起个名」的区别:**
**簇要先证明自己有解释力,才配有名字。**
否则就是给噪声起名字 —— 那恰恰是「压缩不足 = 过拟合」。

## 六、建议五:别只做压缩器,还要做生成器

那段话后半截常被忽略:

> 思维并不只是一个压缩器。它还是一个**生成器**。
> 向后,把复杂世界压缩成简单结构;**向前,从简单结构重新展开出新的可能性。**

你的词表里**这个也已经有了**:**观察剧本**(次日看什么、升级条件、降级条件)。

| 方向 | 你的词 | 状态 |
|---|---|---|
| 向后压缩 | 环境剧本 | 待做 |
| 向前展开 | 观察剧本 | 词表有,终局文档写了,**没落地** |

**而且这两个是同一个对象的两面:**
环境剧本说「历史上这类环境走过几次、后续发生了什么」,
观察剧本说「所以明天盯这几个变量,它们往哪动就升级/降级」。

**观察剧本是压缩模型的「可证伪出口」** —— 没有它,压缩对不对永远无从验证。
它也正好接上你已有的判断轨(`checkpoints.jsonl`,`river_window` 里已经是一维特征了)。

## 七、一个必须装的警告:压缩过度,在你这行叫**刻舟求剑**

在你的领域它有具体形态:**因为 5 个特征对上了,就说 2015 和 2026 是同一类环境。**

### 仓里已经为此吃过一次亏,解法可以抄

`river_window.py:131-141` 把资金维**整维停用**,注释写得很清楚:

> 该维跨 2026-09-02/03 换了口径。**只拦「跨口径两窗直接比较」不够** ——
> z 标准化的均值方差拿**全体日行**算,新口径一进基准,
> **两个同口径旧窗口的 z 值也跟着变**。
> `[实测]` 距离从 **20 掉到 0.001206**,两簇并成一簇。

**教学标签有 `framework_version` / `label_version` —— 同一个陷阱。**
你的框架版本一改,`tf.*` 的历史含义就变了。接进坐标系之前必须先定:
按版本分组标准化?拆成两个特征?还是版本一变整维退出?

### 一条便宜的防刻舟求剑的做法

**报相似窗口时,必须同时报这个簇内部最大的分歧维。**

> 「2016-03 与当下在成交额、涨停数、偏离度上高度相似;
> **但两者的首题材份额差了 3 个标准差** —— 那一轮是单题材独大,这一轮是散。」

成本极低(簇内各维方差排个序),但它逼着每次对标都说出**哪里不像**。
`Cluster.to_dict()` 现在只给 `raw_means`(均值),**加一个 `max_divergence_dims` 就有了。**

## 八、**不**建议做的

### 不要上向量库 / embedding

**你自己的终局文档 §9 第 151 行已经禁了:**

> 不新建「记忆中台」或**第二套向量库**来模拟时间长河。
> 河是索引和对象契约,数据仍在现有轨里。

这条禁令和那段话是**一致的**,不是冲突:

embedding 是**不可回溯的压缩** —— 压完你说不出「为什么这两段像」。
那段话要的压缩是**可解释的**:牛顿的引力、达尔文的自然选择,
**都是能说出来的概念,不是 768 维向量。**

而你现在的 `FeatureSpec` 链恰恰能回答「为什么像」—— **那是优势,不要用 embedding 换掉。**

### 不要先把五个赚钱效应定义合并

先测一致率(§4)。合不合并是你的判断,不是算法的。

### 不要在没数据时先造工具

教学表现在 **0 行**。§2 那个解释力读数,**在没数据之前跑不出任何东西**。
这正是我前几轮犯过六次的毛病(「有库无河」)。**先放水,再量。**

## 九、如果只做一件(**按修正后的目标重排**)

**先测「现在这 10 维里,到底有几个独立维」。**

用 `fact_market_daily` 的 432 天,算这 10 维两两的历史一致度/相关度,
看它们塌成几组。**不需要教学表有数据,今天就能跑。**

为什么这件事排第一:

1. 它直接回答你那句「让行情有**多维度**可以让 agent 看到」——
   **先得知道现在到底有几维。**我怀疑名义 10 维、实际三四维
   (`advancers`/`limit_up`/`max_boards`/`new_high_count`/`double_red_theme_count`
   都在量广度强度)
2. 它同时给出**接教学层的基线**:等放了水,新维度加进来是真的扩了维,
   还是又一组同族读数,**一比就知道**
3. 它是**减少独立事实数量**的第一步 —— 那段话的判据本身

**第二件**才是 §2 的解释力读数(验收增量)。
**第三件**是 §二'' 第二步那四处改动(把空间而不是排名给 agent)——
但那要等维度真的多起来才有意义。

**一句话:先数清楚现在有几维,再谈让 agent 看到多维。**
不然「多维」和我前几轮报的「4 → 27」一样,是个听起来变大了、其实没变大的数。
