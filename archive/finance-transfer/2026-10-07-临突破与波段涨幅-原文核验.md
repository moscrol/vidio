## 二、支撑 / 压力:算了,但只进了「给人看的文字」

### 在哪

`intelligence/services/market_technical.py:427` `compute_technical_levels()`
→ 返回 `supports`(聚类后取 ≤4 档)与 `resistances`(≤3 档)。

**压力位的来源**(`:463` 起):

| 来源 | 实现 |
|---|---|
| 均线 | 高于现价的 MA 全部入选(`:442`) |
| 20 日 / 60 日最高 | `high20` / `high60`(`:464`) |
| 摆动高点 | ❌ **没有**。`_swing_lows` 有(`:366`,`lookback=60, wing=2`),**对称的 `_swing_highs` 不存在** |
| 跳空缺口 | `_gap_zones`(`:379`)只做向上缺口→支撑,未做向下缺口→压力 |

支撑侧比压力侧完整:均线 + 摆动低点 + 20/60 日最低 + 向上跳空缺口,四类;压力侧只有均线 + 20/60 日最高,两类。**不对称是现状,不是设计声明。**

### 它到不了判定路径

```
compute_technical_levels (market_technical.py:427)
        ↑ 唯一调用方
resolve_market_technical (market_technical.py:572)
        ↓
ask / answer 路径 → _render_market_technical_answer (answer_model.py:2246) → 散文
```

在 `teaching_framework/` / `river_derive.py` / `scenario_trees.py` 里 grep `compute_technical_levels`
与 `technical_levels` —— **零命中**。

**这和 P4 是同一个形状:算出来了,只进了人读的句子,没进可判定的路径。**

### 所以「临突破」可以不发明任何东西就拿到

现成的输出里已经有 `close` 和 `resistances[i].zone_low`。距离就是

```
(zone_low / close - 1) * 100       # 离最近一档压力还有百分之几
```

**这不是发明口径 —— 是搬一个已经算好的量。**
「百分之几算临突破」那个阈值仍然是你的判据,由你写在规则里,不由 agent 定。
这正好是 P4 的纪律:**只搬不算**。

⚠ 但有个前提没满足:`compute_technical_levels` 是**按请求现拉 bars 算的**,不是日频批量落库。
要上河需要一个日频批次 + 落 sidecar 表。这一步涉及写库,**我做不了,也不应该替你决定调度口径**。

## 四、波段涨幅:已经在河上了,但口径跟你说的不是一回事

### 现状

`wave_gain_pct` 是一条**完整活着**的链:

| 环节 | 位置 |
|---|---|
| 计算 | `scripts/teaching_framework.py:1501` `WAVE_GAIN_SQL` |
| 落库 | `history_dynasties` / `methodology_backtest/store.py:243` |
| **上河** | `river_objects.py:234` —— **已经读出来进河了** |

口径:`(e.close / b.close - 1) * 100`,区间 `[start_prev, peak_end]`(`:1611`)。**收盘价对收盘价。**

### 「底」和「顶」是怎么定的 —— 这里是分歧点

`intelligence/services/teaching_framework/dynasties.py:82` `segment_waves()`:

```
PEAK_STAGES = ("主流主升", "主流主升2.0", "承接盘反复")    # :39
BUILD_STAGE = "共建主线"                                    # :40

一个波段 = 一段「共建主线」 + 紧随其后连续的 PEAK_STAGES 块
底 = 共建主线段的起点（没有共建段就用峰块起点）       # :112-115
顶 = 峰块最后一段的结束日                              # :125
```

**底和顶不是从价格图上找出来的,是按「大盘周期阶段」切出来的。**

### 跟你的定义比

| | 现有 `wave_gain_pct` | 你说的 |
|---|---|---|
| 底/顶怎么定 | **大盘周期阶段**标签切段 | **看价格图**的形态极值 |
| 层级 | **市场级**波段(王朝),个股只是在这个窗口里量涨幅 | **个股自己**的一波 |
| 粒度 | 只有王朝级大波 | 「**可以是小顶也可以是大顶**」 |
| 价 | 收盘 → 收盘 | (未指定,图上通常看最高/最低) |

**三处都不一致。** 现有的回答的是「在这轮大盘行情里这只股涨了多少」;
你要的是「这只股自己从底到顶走了多少」。一只股票的底比大盘晚 20 天,现有口径就量错了。

### 造你那个定义需要什么

你的定义里唯一没定的是:**什么算一个「底」、什么算一个「顶」**。
「看图就是一小波段」——这是人眼的活,要变成可计算的,必须有个摆动识别参数。

好消息:**机器已经有一半了。**

`market_technical.py:366` `_swing_lows(bars, lookback=60, wing=2)`
—— 「low 低于左右各 2 日的 low」。这就是「底」。

缺的是对称的 `_swing_highs`(第二节说过,不存在),以及 `wing` 取几。
`wing=2` 抓小波段,`wing=5` 抓大波段 —— **这正好对应你说的「可以是小顶也可以是大顶」。**

所以这件事的形状是:**不是缺定义,是缺一个参数档位表**。
和策略口径那次(P3 三档)是同一种解法 —— 不是选一个值,是把档位列出来,让调用方挑。

**这个参数我不替你定。** 但我可以指出:它不需要你讲理论,只需要你看着图说
「这种幅度的波我算一波」,就能反推出 `wing` 该取几。
