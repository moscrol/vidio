# Remotion Component Playbook

用途：把机器人样片和商业航天样片中已经验证过的动态图文卡能力，沉淀成可复用的 Remotion 组件选择手册。本文回答三个问题：一段口播该不该出卡、该用哪类组件、什么时候应该保留 A-roll / B-roll 空间。

## 1. 当前结论

机器人样片验证了 Remotion 原生动态图文卡的可行性；商业航天样片验证了同一批组件可以迁移到第二主题。当前阶段不再以逐帧打磨单条视频为核心，而是进入组件复用和多主题压测阶段。

```text
机器人 → 商业航天压测结论：
1. Industry 7View 版 Swiss 视觉 token 可以复用。
2. cards.js 数据驱动结构可以复用。
3. SRT → card-plan → cards → timeline → motion-plan → Remotion → MP4 流程可以复用。
4. DataHero / Compare / BusinessLoop 原生 Remotion 组件可以跨主题复用。
5. PNG overlay 仍然保留为稳定兜底路径。
```

## 2. 总原则

```text
1. 先判断口播语义，再选择组件。
2. 一张卡只承担一个表达任务。
3. 60-75 秒短视频通常只上 3-5 张卡，不追求全程铺满。
4. 能用 A-roll / B-roll 表达情绪、场景、人物和真实感的地方，不强行上卡。
5. 需要解释结构、数字、对比、闭环和判断时，优先考虑动态图文卡。
6. 新组件进入正式流程前，必须先定义字段边界、适用场景、失败模式和校验方式。
```

## 3. 组件来源选择

| 来源 | 适合场景 | 当前定位 |
|---|---|---|
| `png` | 封面、金句、低频卡、还没有原生组件的卡 | 稳定兜底 |
| `remotion` | 数字、对比、闭环、流程、节点点亮 | 优先复用和扩展 |
| `stitch` | 新布局探索、视觉资产参考、外部设计稿 | 设计来源，不直接接管渲染 |

当前 Remotion native 类型由 `scripts/prepare-remotion-assets.mjs` 中的 `nativeCardTypes` 控制：

```text
dataHero
compare
loop
```

对应组件：

```text
remotion/components/DataHeroMotion.tsx
remotion/components/CompareMotion.tsx
remotion/components/BusinessLoopMotion.tsx
```

## 4. 已验证组件

### 4.1 CoverCard

**用途**

开场定调、发布封面、主题认知框架。

**适合口播**

```text
这个行业不是 X，而是 Y。
真正的拐点不是 A，而是 B。
别只看表面动作，要看背后的商业逻辑。
```

**字段重点**

- `kicker`：品牌/主题短标签。
- `titleHtml`：一句反常识判断。
- `subtitle`：补充真正要讲的逻辑。
- `badge`：主题名。

**复用案例**

- 机器人：不是来跳舞的，真正拐点是进工厂干活。
- 商业航天：真不是发火箭，火箭只是入口，真正值钱的是持续收费。

**失败模式**

- 标题同时塞两个判断。
- 副标题解释太长，开场 3 秒读不完。
- 用封面承担中段解释任务。

**建议时长**

```text
2-4 秒
```

---

### 4.2 DataHeroMotion

**用途**

突出一个关键数据，让观众记住数量级。

**适合口播**

```text
2-3 万美元。
20 万颗。
不足 30%。
万颗级星座。
```

**字段重点**

- `value`：主数字，只放一个核心数字。
- `unit`：单位。
- `label`：这个数字代表什么。
- `compare`：与谁对比。
- `insight`：数字背后的判断。

**复用案例**

- 机器人：Optimus 量产目标价 2-3 万美元。
- 商业航天：可用于 20 万颗低轨星座、不足 30% 有效服务应用、万颗级组网等数字。

**失败模式**

- 一张数据卡放多个数字。
- 数字很大但没有解释“为什么重要”。
- 数据没有和口播时间点对齐，导致卡片提前出现。

**建议时长**

```text
5-8 秒
```

**是否优先 native**

```text
是。数字滚动、单位弹出、强调线和网格微动都适合 Remotion 原生动画。
```

---

### 4.3 CompareMotion

**用途**

纠正误解、制造转折、区分两个容易混淆的概念。

**适合口播**

```text
Demo 不等于产品。
发射成功不等于商业闭环。
能上天不等于能赚钱。
概念热不等于业绩兑现。
```

**字段重点**

- `leftLabel` / `rightLabel`：两侧概念。
- `leftText` / `rightText`：各自含义。
- `explain`：一句话讲清判断。

**复用案例**

- 机器人：Demo ≠ 产品。
- 商业航天：发火箭 ≠ 商业航天，卫星上天 ≠ 公司赚钱。

**失败模式**

- 左右两边不是同一层级概念。
- 对比不是冲突，只是并列。
- 解释语太长，导致观众只看到形式没理解判断。

**建议时长**

```text
5-8 秒
```

**是否优先 native**

```text
是。左右滑入、分割线、金色强调和解释 reveal 已经验证可复用。
```

---

### 4.4 BusinessLoopMotion

**用途**

解释商业闭环、产业链赚钱路径、量产路径、现金流循环。

**适合口播**

```text
低成本发射 → 批量造卫星 → 低轨星座组网 → 地面终端连接 → 下游应用付费。
低成本发射 → 批量组网 → 用户付费 → 现金流反哺研发。
百万台级别 → 成本压低 → 批量制造 → 稳定交付 → 客户付费。
```

**字段重点**

- `titleHtml`：闭环主题。
- `steps`：3-5 个节点。
- `footer`：一句结论。

**复用案例**

- 机器人：量产不是研发成功，而是成本、制造、交付和客户付费闭环。
- 商业航天：低成本发射到下游应用付费的商业闭环。

**失败模式**

- 节点超过 5 个。
- 口播只是在列清单，不是真正闭环。
- 停留时间过长，观众读完后画面没有新信息。
- 节点名过长，导致路径动画被文字压住。

**建议时长**

```text
7-12 秒
```

商业航天中的 6.9s-21.6s 闭环段可作为边界样本：如果完整段落接近 15 秒，应考虑拆成“闭环卡 + B-roll”而不是让同一张卡长时间停留。

**是否优先 native**

```text
是。路径推进、节点逐个点亮、最终节点强调都适合复用。
```

---

### 4.5 LogisticsCard

**用途**

用生活类比解释复杂系统，降低理解门槛。

**适合口播**

```text
火箭像快递车。
卫星像天上的基站。
测控系统像交通指挥中心。
地面终端像卫星路由器。
```

**字段重点**

- `frames` / `items`：一组映射关系。
- 每个映射应是“复杂对象 = 熟悉对象”。
- 结论要回到产业判断，而不是只做比喻。

**复用案例**

- 商业航天：太空新基建。
- 其他潜在主题：算力中心 = 工厂，电网 = 运输系统，半导体设备 = 工艺工具箱。

**失败模式**

- 映射超过 4 组。
- 类比漂亮但没有回到商业逻辑。
- 文字过多，短时间读不完。

**建议时长**

```text
6-10 秒
```

**是否优先 native**

```text
暂不优先。当前可继续使用 PNG overlay，等多个主题都反复需要“类比映射动画”后再升级。
```

---

### 4.6 TrackingChecklistCard

**用途**

把结论变成跟踪指标，让观众知道后续看什么。

**适合口播**

```text
看商业航天，盯三个变量。
可回收火箭，是成本账。
星座组网，是进度账。
用户付费，是收入账。
```

**字段重点**

- `items`：3 个最重要变量。
- 每项最好是“指标 + 判断含义”。
- 不要写成泛泛建议。

**复用案例**

- 机器人：进工厂、不坏、不贵。
- 商业航天：成本账、进度账、收入账。

**失败模式**

- 清单超过 3-4 项。
- 指标不可观察。
- 只是总结前文，没有给出后续跟踪动作。

**建议时长**

```text
6-9 秒
```

**是否优先 native**

```text
候选。适合做逐项打勾、风险状态切换，但应等第三主题压测后再决定是否升级。
```

---

### 4.7 ClosingQuote

**用途**

结尾收束观点，强化一句可传播判断。

**适合口播**

```text
不是能不能上天，而是能不能赚钱。
样品时代刚结束，产品时代刚开始。
三本账对上了，题材才变成生意。
```

**字段重点**

- `quote`：一句主判断。
- `caption`：解释性短句，可选。
- 不增加新信息。

**复用案例**

- 机器人：样品时代刚结束，产品时代刚开始。
- 商业航天：不是能不能上天，而是能不能赚钱。

**失败模式**

- 结尾又开始讲新概念。
- 金句和口播最后一句不一致。
- 画面太复杂，削弱收束感。

**建议时长**

```text
5-8 秒
```

**是否优先 native**

```text
暂不优先。PNG overlay 已足够稳定，除非后续需要统一结尾动画品牌化。
```

## 5. 一条视频的卡片密度

60-75 秒视频建议按以下节奏安排：

| 时间段 | 推荐画面 | 目的 |
|---|---|---|
| 0-3s | A-roll / CoverCard | 建立判断和主题 |
| 3-15s | Compare / Hook / BusinessLoop | 制造转折或解释主逻辑 |
| 15-35s | Logistics / BusinessLoop / B-roll | 讲清系统结构 |
| 35-50s | DataHero / Checklist / B-roll | 给出关键数字或跟踪指标 |
| 50-75s | ClosingQuote / A-roll | 收束观点和互动 |

关键规则：

```text
不要因为时间线上有空白就强行补卡。
```

商业航天 36s-45s 的留白可以视为正常发布空间，适合后续剪入火箭发射、卫星组网、地面终端、遥感应用、地球轨道动画等 B-roll。

## 6. 什么时候不上卡

以下情况优先保留 A-roll / B-roll：

```text
1. 口播在讲情绪、判断、反问、互动。
2. 需要真实场景增强可信度。
3. 已经连续出现两张信息卡。
4. 当前段落没有新结构、新数字或新对比。
5. 卡片会挡脸，且画面主体本身有表达价值。
6. 文字需要超过 10 秒才能读完。
```

## 8. 下一批候选组件

### 8.1 OrderValidationCard

**用途**

表达从验证到收入兑现的阶段链。

**适合主题**

```text
半导体设备、机器人量产、服务器电源、商业航天订单兑现。
```

**典型结构**

```text
样机 → 客户验证 → 小批量导入 → 批量订单 → 收入 / 毛利兑现
```

**与 BusinessLoop 的区别**

BusinessLoop 讲商业循环；OrderValidationCard 讲订单兑现的阶段门槛。

---

### 8.2 SupplyChainShiftCard

**用途**

表达产业链价值和话语权从一个环节迁移到另一个环节。

**适合主题**

```text
CPO、高速铜缆、服务器电源、半导体设备、商业航天下游应用。
```

**典型结构**

```text
原价值中心 → 新增瓶颈 → 价值迁移 → 谁更受益
```

**与 TrackingChecklist 的区别**

TrackingChecklist 给跟踪指标；SupplyChainShiftCard 解释价值为什么换位置。

---

### 8.3 TechRouteCompareCard

**用途**

比较多条技术路线的差异和产业化路径。

**适合主题**

```text
固态电池、可控核聚变、6G、半导体材料、商业航天通信路线。
```

**典型结构**

```text
路线 A：优势 / 短板 / 进度
路线 B：优势 / 短板 / 进度
路线 C：优势 / 短板 / 进度
```

---

### 8.4 PipelineStageCard

**用途**

表达研发、临床、审批、商业化等阶段推进。

**适合主题**

```text
创新药、医疗器械、合成生物、商业航天型号研制。
```

**典型结构**

```text
发现 / 研发 → 验证 → 审批 → 放量 → 商业化
```

## 9. 进入正式组件库的标准

一个候选组件只有满足以下条件，才进入正式开发：

```text
1. 至少在 2 个真实主题中反复出现。
2. 现有卡片无法清晰表达它。
3. 字段结构可以稳定抽象。
4. 能定义明确的字数和节点上限。
5. 有明确的 Remotion 动效收益。
6. PNG 兜底方案仍然可用。
```

## 10. 当前推荐下一步

```text
1. 冻结商业航天 Remotion 压测版，不继续逐帧打磨。
2. 用第三个差异化题材压测组件边界。
3. 优先选择半导体设备、CPO 或固态电池。
4. 观察是否需要开发 OrderValidationCard、SupplyChainShiftCard 或 TechRouteCompareCard。
5. 每次压测后更新本文和 COMPONENT_GAP_LOG.md。
```
