# 内容公式：项目锚定的通用技术讲解

as-of: 2026-07-11  
status: **主叙事口径**（用户确认方向）

---

## 你要做的（一句话）

> **围着自己正在做的项目**，讲开发时撞到的**通用痛点** + **热门技术**（RAG / 防幻觉 / 输出质检 / ingest…），  
> 用真实实例把知识点讲透，并给出**可复用场景**；产品只**隐含出现**，不硬广、不急获客。

真实感来自：「我在做系统时遇到了…」，不是「今天给大家安利…」。

---

## 单条标准结构（20–40s 默认）

```
① 现场痛点（开发时的坑 / 一次翻车）     3–5s  情绪或屏幕故障感
② 这其实是通用问题（点名技术词）       3s   RAG / 幻觉 / ingest / 质检…
③ 第一性或结构图（一层就够）           8–15s 大白话 + 一图
④ 我项目里怎么落的（实例，点到为止）   5–10s 不泄密钥、不念绝对路径
⑤ 你也可以用在哪（可复用场景 1–2 个）  3–5s  客服 / 研究 / 代码库 / 知识库…
⑥ 开放问题                             结尾  讨论，不要下载
```

**隐含产品**：④ 里自然出现「研究 Agent / 知识库 / 信息流」即可，不报功能清单、不报票、不挂链。

## 热门技术 × 你的实例地图

| 通用知识点（观众能搜） | 开发痛点（开场） | 你侧实例锚（隐含产品） | 笔记/仓 |
|------------------------|------------------|------------------------|---------|
| **防幻觉 / grounding** | 模型说得真像那么回事 | 五层：生成→证据→校验→重放→金标准；权限单独一层 | 70_tutor 五层防幻觉 |
| **输出质量把控** | 答得对也不该自动写库/决策 | verifier、answer-score、lint 门 | skill+verifier；workspace eval |
| **检索前置 / RAG** | 秒回往往是没查就编 | 触发表：命中就强制检索；快答=检索后短答 | 检索前置硬触发 |
| **GraphRAG** | 「A 和 B 啥关系」向量答不好 | concept_graph / 暴露边 / hybrid routing | GraphRAG 低配实现；KB |
| **数据 ingest** | 扫了一千条 ≠ 知识建好 | processed≠applied；回执；禁静默跳过 | 数据量不是完成度；concept/entity/pdf-ingest |
| **知识闭环 / 契约** | 管线跑完了心里没底 | 事实·概念·关系·PIT·receipt 五层 | 同上 |
| **头尾分治 / skill** | 不是每个问题都该写 skill | 头部 skill、长尾自由编排+护栏 | 长尾；编排层 |
| **路由 / 编排** | 平铺 skill 规则散落 | 问答总台 vs 写库直达双轨 | 单入口派单 |
| **记忆冲突** | 共享库说 A、用户笔记说 B | prior + 数据三角验证；防自我强化 | 记忆 prior |
| **最小权限** | agent 工具太多等于权限太大 | preset：researcher/producer/reviewer | preset 权限 |
| **结论腐烂 / 跟踪** | 周报全是复读 | TTL + delta-only + 观点四态 | 结论 TTL |
| **Prompt 暴露** | 当机密的 prompt 一问就倒 | 默认会被读到；护城河在数据层 | 自我暴露面 |
| **信息减噪**（次要） | 源太多读不完 | FinHot 聚合/打分——仅作减噪案例 | finhot |
| **端到端研究**（少而精） | 一次问答要像报告 | Deep Fomo 深挖链路——架构印证用 | workspace + kit |

选题优先级：**上表前 8 行 > 产品演示**。金融场景只是「实例皮肤」，通用点才是标题和搜索词。

## 标题 / 钩子怎么起（服务真实感）

优先句式：

| 类型 | 例 |
|------|-----|
| 翻车现场 | 「模型一本正经编了个财报数字」 |
| 否定纠偏 | 「生成不是真相」 |
| 对比 | 「入库一千条，知识就齐了？」 |
| 开发者共鸣 | 「不是所有问题都值得写 skill」 |
| 热词+痛点 | 「RAG 召回了一堆，还是答不对关系」 |

标题露 **通用技术词**（防幻觉、RAG、ingest、质检），产品名尽量不露或极弱。

## 和「获客 / 证据 / AI HOT」的关系

| 元素 | 角色 |
|------|------|
| 自己的项目 | **主锚**，故事与可信度来源 |
| 70_tutor | 已蒸馏的原理与比喻，加速写稿 |
| 热门技术词 | 搜索与完播钩子，不是蹭流量空壳 |
| 隐含产品 | ④ 里带过即可 |
| AI HOT | 可选：热点当开场「圈里在吵 X」，立刻收到你的坑与解法 |
| 证据等级 | 方向参考即可，不为统计表演牺牲真实感 |

## 不要做成什么样

- 功能清单 / 60s 产品介绍（已踩坑）  
- 纯概念课、零项目锚（假大空）  
- 纯项目 vlog、无可复用点（别人学不走）  
- 荐股、报票、收益承诺  
- 每条都深挖一只股票  

---

## 可复用场景库（结尾常用）

每条结尾挑 1 个，降低「只懂金融」的窄感：

1. 企业知识库问答  
2. 客服 / 工单 agent  
3. 代码库 + 文档助手  
4. 研报/PDF 入库流水线  
5. 多源记忆冲突的个人第二脑  
6. 任何「LLM 输出要不要自动写库」的系统

## 前几条建议顺序（贴合本公式）

1. 防幻觉：生成不是真相（翻车 → 五层 → 可复用）  
2. 正确 ≠ 有权决策（质检/权限）  
3. ingest：数据量不是完成度  
4. 检索前置 / RAG 没查就编  
5. skill 头尾分治  
6. GraphRAG 关系题  
7. （偶插产业或工程日记）  
8. verifier 输出质检  
…
